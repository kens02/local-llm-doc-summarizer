# 要件定義書

## 1. 目的
指定されたテキスト/ドキュメントファイルを Local LLM で要約し、その内容についてチャット対話できるサービスを構築する。イメージについては簡易的な NotebookLM 風の体験を提供する。

## 2. 対象範囲
### 2.1 対象ファイル
- `aa.txt`
- `aa.md`
- `aa.pdf`
- `aa.docx`

### 2.2 利用者
- ドキュメント内容の要約を迅速に把握したいユーザー
- 要約内容や原文に対して対話的に確認したいユーザー

## 3. 機能要件
### 3.1 ファイル入力
- 指定された 4 種類のファイル形式（txt / md / pdf / docx）を取り込めること。
- ファイルはローカル環境上に存在することを前提とする。

### 3.2 要約生成（Local LLM）
- 取り込んだファイルの内容を Local LLM で要約できること。
- 要約は読みやすい文章として出力されること。
- 要約の長さは「1分程度で読めるボリューム」を目安に文字数を検討すること。
- 要約のスタイルは「箇条書き」「文章」の2パターンから選択できること。
- 要約対象の原文が大きい場合は、分割処理などで安定して要約できること。

### 3.3 対話（Chat）
- 要約内容および原文に対して質問・対話ができること。
- ユーザーの質問に対して、要約と原文の両方を参照して回答できること。
- チャットの履歴は保存し、チャットルームごとに再開できること。

### 3.4 イメージ（簡易的 NotebookLM）
- ドキュメントの内容をもとに、簡易的な「ノート化／整理ビュー」を提供すること。
- 例: 見出し構造、要点箇条書き、キーフレーズのハイライトなど（簡易でよい）。

### 3.5 多言語対応
- 日本語、英語、中国語の3種類に対応すること。

## 4. 非機能要件
### 4.1 実行環境
- ローカル環境で動作すること（外部クラウドへの依存は最小化）。

### 4.2 応答性能
- 一般的なドキュメント（数十ページ程度）であれば実用的な時間で要約が完了すること。

### 4.3 使いやすさ
- ユーザーがファイルを指定し、要約・対話まで迷わず利用できること。

## 5. 前提条件
- Local LLM はローカル環境にセットアップ済みであること。
- 対象ファイルは文字化けや破損がない前提とする。

## 6. 制約事項
- 外部APIに依存しない、もしくは依存を最小限に抑える。
