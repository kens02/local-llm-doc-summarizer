# 汎用テンプレート 作成プロンプト（Copilot用）

「試験シナリオ一覧」と「構成要素一覧」の汎用テンプレートを、Copilotで作り直るプロンプト集です。

## 使い方

- **共通前提（P0）を毎回の先頭に付けて**、各プロンプトを順に実行します。
- ブックごとに分かれています。A＝試験シナリオ一覧、B＝構成要素一覧。
- 想定する手順：新規ブックを作る → 各プロンプトで表を作る → シートに貼り付ける → 式・入力規則・書式を設定する。
- Copilotの種類によって、シートの新規作成や入力規則の設定ができない場合があります。その場合は表と手順だけ出力させて、設定は手作業で行ってください。
- 1回に入力できる長さには上限があります（上限値は要確認）。タブ区切りのデータが長いときは、前半と後半に分けて渡してください。
- データ（タブ区切り）は**そのまま貼り付ける**のが確実です。Copilotにはデータを作らせず、書式・式・入力規則の設定に使うと食い違いが起きにくくなります。

---

## P0 共通前提（毎回先頭に貼る）

```
あなたはソフトウェア開発のプロジェクト管理と品質管理に詳しいアシスタントです。
AIを使った開発効率化環境を検証・評価するための、汎用の管理テンプレートをExcelで作成しています。
テンプレートは2つのブックからなります。
- 試験シナリオ一覧.xlsx：工程×ユースケースごとに、AIの使い方・検証計画・結果・成果物を管理する
- 構成要素一覧.xlsx：開発環境を構成するツール・モデル・基盤を台帳として管理する
2つのブックは「構成要素ID（T-連番）」と「UC-ID」で双方向に紐づけます。

【共通ルール】
- フォントはメイリオ UI、11pt。
- 1行目にシートのタイトル（14pt太字）、2行目に説明（9pt灰色）、4行目に見出し、5行目からデータを置く。
- 見出し行は濃紺の背景に白の太字で、中央揃え・折り返し。
- 入力欄は薄い黄色、自動計算の列は薄い灰色、記入例の行は薄い緑で塗る。
- セルは折り返して表示し、上詰めにする。罫線は薄い灰色の細線。
- 見出し行と左側のID列でウィンドウ枠を固定し、見出しにフィルターを設定する。
- プルダウンは「マスタ」シートの範囲を参照する。
- 私が示したデータ・式・列名は、内容を変えたり、項目を追加・削除したりしない。
- 不明な点は推測で埋めずに「要確認」と書く。
```

# A. 試験シナリオ一覧

## A-1 シート構成・マスタ・使い方

```
「試験シナリオ一覧」ブックを作成します。シートはこの順番にしてください：使い方 → カラム定義 → ユースケース一覧 → 試験シナリオ一覧 → 成果物一覧 → カバレッジ → マスタ

まず「マスタ」シートと「使い方」シートを作ってください。

【マスタ】1行目を見出しにし、列ごとに次の選択肢を2行目から縦に並べる。
A 工程：共通／要件定義／基本設計／詳細設計／製造／単体テスト／結合テスト
B 種別：プチ検証／トライアル
C ステータス：未着手／準備中／実施中／完了／保留／中止
D 結果：合格／条件付合格／不合格／判定保留
E 優先度：A／B／C
F 未経験者支援：◎／○／―
G 構成要素分類：AIモデル／推論基盤／コーディング支援・エージェント／RAG・検索／オーケストレーション／開発環境（IDE）／構成管理・CI/CD／プロジェクト・チケット管理／ドキュメント・ナレッジ／文書変換・出力／図・モデリング／テスト・品質／セキュリティ・認証・秘密情報／監視・運用／インフラ（HW・OS）／その他
H 取扱区分：公開／社内／機密／要確認
I 成果物種別：テンプレート／プロンプト／手順書／チェックリスト／開発フロー／ルールファイル
J 成果物状態：作成中／レビュー中／確定／廃止

【使い方】A列に項目名、B列に説明を書く（B列は幅95程度で折り返す）。1行目にタイトル「試験シナリオ一覧（汎用テンプレート）— 使い方」。
「【】」で囲んだものは見出し行（A列のみ太字）として入れる。
- 目的：AIを使った開発効率化を、どの工程のどの作業で、何をもって効果ありとするかを計画・記録し、網羅的に評価する。
【シート構成】
- カラム定義：各シートの列の用途と入力ルール。迷ったらここを見る。
- ユースケース一覧：工程×作業ごとに「AIに何をさせるか」を定義する（叩き台付き）。
- 試験シナリオ一覧：ユースケースごとの検証計画と結果。UC-IDを入れると工程・作業名が自動表示される。
- 成果物一覧：検証で作ったテンプレート・プロンプト・手順書を管理する。
- カバレッジ：工程別の網羅状況・進捗を自動集計する。
- マスタ：プルダウンの選択肢。プロジェクトに合わせて変更する。
- 構成要素一覧との関係：「構成要素一覧（ツール台帳）」と組み合わせて使う。ユースケースと試験シナリオの「構成要素ID」列にツール台帳のIDを入れ、ツール台帳の「関連UC-ID」列にUC-IDを入れて双方向に紐づける。
- 進め方：①ユースケースの追加・削除と優先度を関係者と合意 → ②優先度Aからシナリオを起票（合否基準を事前に合意）→ ③プチ検証を実施して成果物を作る → ④トライアルで工程を通して確かめる → ⑤成果物を開発フロー・手順書にまとめる
【凡例】
- 黄色セル：入力欄
- 灰色セル：自動計算（編集しない）
- 緑色セル：記入例。実データを入れるときに削除または上書きする
- 種別：プチ検証＝1ツール×1ユースケースで動作・精度・時間短縮を短時間で確認する。トライアル＝複数工程を通しで回す模擬開発で、テンプレート・手順が実際に使えるかを確認する。
- 優先度：A＝本番開始までに必須／効果が大きい、B＝段階導入でも可、C＝余力があれば
- IDルール：UC＝工程略号-連番（CMN/REQ/BD/DD/IMP/UT/IT）、シナリオ＝SC-連番、成果物＝PR-連番、構成要素＝T-連番
- 計測のコツ：AIありの所要時間には、出力の確認・修正にかかった時間も含める。AIなしの時間は同じ作業を従来の方法で行った実績か見積りを使い、どちらかを備考に書く。
- 注意：入力データの取扱区分を必ず確認し、利用が許可された環境・データだけで検証する。
```

- 構成要素一覧：ツール台帳の本体。1行＝1構成要素。
- 集計：分類別・工程別の件数と、リスクのある構成要素・ツールが不足している工程を自動で表示する。
- マスタ：プルダウンの選択肢。プロジェクトに合わせて変更する。
- 試験シナリオ一覧との関係：「試験シナリオ一覧」と組み合わせて使う。この台帳の「関連UC-ID」にユースケースのIDを入れ、試験シナリオ側の「構成要素ID」にこの台帳のIDを入れて双方向に紐づける。「分類」の選択肢は試験シナリオ一覧の「想定ツール分類」と同じにしておく。

- 黄色セル：入力欄
- 灰色セル：自動計算（編集しない）
- 緑色セル：記入例。実データを入れるときに削除または上書きする
